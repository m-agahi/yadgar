# v5.1.0 — server / storage module split

**Status:** planned. Lands in PR #66 after v5.0.1 ships from PR #65.
**Semver:** minor (5.0.x → 5.1.0). Import paths change for downstream consumers; the public MCP surface is unchanged.
**Motivation:** `server.py` (4 268 LOC, 97 top-level defs, 39 `@_tool` decorations) and `storage.py` (3 736 LOC, ~115 public methods on `StorageEngine`) are the two largest source files in the repo and the dominant rebase-conflict surface for any concurrent change.

## Context

Inventory captured against master tip `042f42b`:

| File | LOC | Top-level defs | Notes |
|---|---:|---:|---|
| `yadgar/server.py` | 4 268 | 97 | 39 `@_tool` decorations (15 plain, 24 `power=True`) |
| `yadgar/storage.py` | 3 736 | 7 module-level + ~115 `StorageEngine` methods | All methods on one class |

Stage 11 (v5.0) decomposed `retrieval/core.py::recall` and `causal_discovery.py::pc_algorithm` safely because Stage 6 wrote **characterization tests** pinning their behavior. `server.py` and `storage.py` have no equivalent. Splitting them without that gate multiplies the kind of copy-paste oversight that produced **C-1** (auth middleware missing from SSE transport — found in the 2026-05-16 review).

The gate must be built first.

### Circular-import guard

A test that does `import yadgar.server` cold, without engine initialization. The split must preserve the lazy-import pattern that `file_queue.py` and `consolidation.py` already use to avoid module-load-time cycles.

```python

    import sys
    sys.modules.pop("yadgar.file_queue", None)
    sys.modules.pop("yadgar.consolidation", None)

    assert "yadgar.consolidation" not in sys.modules
```

## Stage 4 — Test-suite performance

Current state (read-only investigation 2026-05-16):

- **57+ min** CI wall-time on 1 526 tests / 92 files
- **CI runs `-n auto` on a 2-vCPU runner** — that's 2 workers, not the `-n 4` declared in `pyproject.toml`
- **34 files marked `pytest.mark.xdist_group("server_globals")`** (Stage 13 mask). 761 of 1 526 tests = **50% of the suite** serialized into one worker
- **`_isolate_surrealdb` autouse fixture** calls `_init_schema()` per test: 1 526 × 30–50 ms ≈ 30–76 s overhead
- **`embeddings` session fixture exists in `conftest.py`** but `test_curation.py` and `test_consolidation.py` define **function-scoped overrides** that rebuild `EmbeddingEngine` per test. `test_curation.py` also constructs one at module import.
- **`--reruns 2 --reruns-delay 2` applied globally in CI** — no tests have `@pytest.mark.flaky`, so the global rerun is overkill
- **`surreal_server`** itself is correctly session-scoped, single-process, SIGKILL escalation on teardown — no change needed

### Wall-time opportunities (ranked by impact)

| # | Change | Est. saving | Risk |
|---|---|---:|---|
| 1 | Promote CI runner from 2-vCPU `ubuntu-latest` to 4-core (or self-hosted) — match `-n 4` from pyproject. Removes the half-suite tail wait. | 15–25 min | Infra change; needs runner config |
| 2 | Cache `_init_schema()` per DB namespace in `_isolate_surrealdb` — `_SCHEMA_INITIALIZED: set[str]` guard so already-init'd DBs skip the round-trip | 5–15 min | Low; pure caching |
| 3 | Remove function-scoped `embeddings` overrides in `test_curation.py` and `test_consolidation.py`; drop module-level `_engine = EmbeddingEngine()` at `test_curation.py:19` | 3–8 min | Low; just deletes lines |
| 4 | Switch CI `--dist` to `worksteal` while keeping `loadgroup` for `xdist_group`-marked tests — lets the free worker steal idle work from the serialized one | 2–4 min | Low; needs flag tweak |
| 5 | Mark characterization suites `@pytest.mark.slow` + skip-by-default; opt-in via `pytest -m slow` for the v5.1 split work and final-PR audits only | 2–5 min | Low; tests still run on demand |
| 6 | Drop `--reruns 2 --reruns-delay 2` globally; add `@pytest.mark.flaky(reruns=2)` to specific xdist-isolation flakes if they reappear | 0–2 min steady; removes latency tax on actual failures | Low |
| 7 | **Fix the state leak that forced 34 `xdist_group` markers** (task #15, still pending). Once fixed, remove the markers and let the full suite parallelize | 10–20 min | High effort; proper fix |

### Subprocess-leak hardening (test surreal-server)

**Observed 2026-05-16:** 93 stale `surreal start` subprocesses on local host, ~12 GB RSS, on a 64 GB box. Two contributors:

| Source | How it leaks | Fix |
|---|---|---|
| Local agent worktrees running pytest | Worktree gets reaped by Claude harness mid-run; surreal subprocess survives | PID-file tracking + cross-session reap |
| Self-hosted CI runner accepting concurrent jobs | `concurrency.group: ${{ workflow }}-${{ ref }}` cancels only within same ref; master + PR + tag pushes run three concurrent surreals | Drop `-${{ ref }}` suffix → global single-slot |

#### `surreal_server` hardening (`yadgar/tests/conftest.py`)

```python
import atexit, os, signal
from pathlib import Path

_PID_DIR = Path("/tmp/yadgar-test-surreal")
_PID_DIR.mkdir(exist_ok=True)


def _count_alive_pids() -> int:
    alive = 0
    for pf in _PID_DIR.glob("surreal-*.pid"):
        try:
            pid = int(pf.read_text().strip())
            os.kill(pid, 0)  # existence check
            alive += 1
        except (FileNotFoundError, ValueError, ProcessLookupError):
            pf.unlink(missing_ok=True)
    return alive


@pytest.fixture(scope="session", autouse=True)
def surreal_server(tmp_path_factory):
    if (stale := _count_alive_pids()) > 5:
        pytest.exit(
            f"Refusing to spawn — {stale} stale surreal processes alive. "
            f"Run scripts/kill-stale-surreals.sh first."
        )
    # ... existing spawn body ...
    (_PID_DIR / f"surreal-{port}.pid").write_text(str(proc.pid))

    def _cleanup():
        try:
            os.kill(proc.pid, signal.SIGKILL)
        except ProcessLookupError:
            pass
        (_PID_DIR / f"surreal-{port}.pid").unlink(missing_ok=True)

    atexit.register(_cleanup)
    yield ...
    _cleanup()
```

#### `scripts/kill-stale-surreals.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail
before=$(pgrep -fc "surreal start" || true)
for pid in $(pgrep -f "surreal start"); do
  args=$(ps -o args= -p "$pid" 2>/dev/null || true)
  case "$args" in
    *"bind 0.0.0.0:8000"*) : ;;   # production daemon — keep
    *) kill -9 "$pid" 2>/dev/null || true ;;
  esac
done
rm -f /tmp/yadgar-test-surreal/*.pid
echo "Surreal: ${before} -> $(pgrep -fc 'surreal start' || true)"
```

#### CI concurrency change (`.forgejo/workflows/ci.yaml`)

```yaml
# Before — cancels only within same ref; cross-ref parallel on self-hosted
concurrency:
  group: ${{ github.workflow }}-${{ github.ref }}
  cancel-in-progress: true

# After — global single-slot per workflow
concurrency:
  group: yadgar-ci-${{ github.workflow }}
  cancel-in-progress: false   # queue, don't cancel
```

Tradeoff: queue depth grows on push storms, but at most one CI surreal alive at any moment on the self-hosted runner.

#### Document in `docs/claude-workflow.md`

> **Agent worktree subprocess leak guard.** When dispatching `Agent(isolation="worktree", run_in_background=true)` for any task running pytest, the `surreal_server` fixture spawns a subprocess. If the agent task is killed (timeout, harness reap, OOM), that subprocess survives. Before launching a new agent batch, run `scripts/kill-stale-surreals.sh` if `pgrep -fc "surreal start"` returns more than ~3.
>
> The fixture writes a PID file at `/tmp/yadgar-test-surreal/surreal-<port>.pid` so subsequent test sessions detect and reap stale instances at startup. Sessions abort if more than 5 stale survive.
