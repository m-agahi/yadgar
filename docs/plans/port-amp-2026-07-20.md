## Verified contract

**Config file location:**
Amp has two hook surfaces:
1. `amp.hooks` settings (JSON in `~/.config/amp/settings.json`) — config-only, **no shell-out**
2. **TS plugins** (`~/.config/amp/plugins/` or `.amp/plugins/`) — shell-out supported;
   this is the useful path for yadgar

Shell-out from plugins is confirmed functional. `amp.hooks` settings alone cannot
invoke external processes.

**Real event names (5 plugin events, verified at ampcode.com/manual + ampcode.com/manual/plugin-api):**
`session.start`, `agent.start`, `tool.call`, `tool.result`, `agent.end`

**Inject mechanism:**
TS plugins. `agent.start` returns `{message: {content: "...", display: false}}` to
inject context before the agent turn starts. `session.start` is void (no return value
for inject); use `agent.start` + first-turn guard for session-start equivalent.

- `agent.start` → return `{message: {content, display: false}}` = inject (user-prompt equivalent)
- `session.start` + first-turn guard → session-start inject (via `agent.start` on turn 1)
- `tool.result` → full tool result context; capture to yadgar action log
- `tool.call` → **blocking**; can allow/reject/modify/synthesize tool calls
  (`synthesize` = return fabricated result without running tool)
- `agent.end` ≈ Stop → non-blocking POST; fires after agent turn completes

**Synthesize note:** `tool.call` with `synthesize` action returns a fabricated
`tool.result` to the model without running the actual tool. This is more powerful
than simple allow/deny — potential for yadgar context injection via tool shim.
Not mapped to a core need; flag for future use.

**No `PreCompact` equivalent:** Amp has no compaction event. Drain must be periodic
(via `tool.result` cadence) or deferred to `agent.end` best-effort.

## Per-need mapping

| Need | Status | Mechanism |
|------|--------|-----------|
| Session-start inject | FUNCTIONAL | `agent.start` + first-turn guard → `{message: {content, display: false}}` |
| User-prompt inject | FUNCTIONAL | `agent.start` → same return mechanism (fires each agent turn) |
| Post-tool capture | FUNCTIONAL | `tool.result` → full context object; `yadgar hook postToolUse` |
| Pre-compact drain | NONE | No PreCompact event; periodic `tool.result` drain or async `agent.end` fallback |
| Stop checkpoint | NONE (non-blocking) | `agent.end` non-blocking POST; async checkpoint only |

**Coverage: 3/5 functional, 2/5 none (no drain, no blocking Stop).**

## Build scope

Wire in `hooks_render.py` replacing Amp `_emit_stub` (TS plugin path):

1. `agent.start` (session-start inject, first-turn guard) → call `yadgar hook sessionStart`;
   return `{message: {content: <result>, display: false}}`
2. `agent.start` (user-prompt inject, subsequent turns) → call `yadgar hook userPromptSubmit`;
   return `{message: {content: <result>, display: false}}`
3. `tool.result` → call `yadgar hook postToolUse` with result context; no return
4. `agent.end` → async `yadgar hook stop`; no return (non-blocking)

Plugin file written to `~/.config/amp/plugins/yadgar-hooks.ts`.
`install_hooks --client amp` generates plugin + registers in `amp.hooks` settings
(for any config-only entries) + writes plugin file.

Rules file: AGENTS.md (Amp primary format; hierarchical lookup includes
`~/.config/amp/AGENTS.md` for global). `sync_instructions --target amp` writes
`~/.config/amp/AGENTS.md`.

## Open questions / live-tests

- **First-turn guard implementation:** verify `agent.start` payload includes session ID
  or turn counter so guard can distinguish session-start from subsequent turns
- **`tool.call` synthesize for inject:** evaluate whether synthesize action can serve
  as an alternate inject channel (richer than message prepend); spike needed
- **`display: false` behavior:** confirm injected message is invisible to user in Amp UI
  (per docs claim) vs appearing as a system message
- **Periodic drain cadence:** determine acceptable drain frequency via `tool.result`
  hook to approximate PreCompact behavior
